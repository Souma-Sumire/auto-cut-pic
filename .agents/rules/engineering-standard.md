# 现代软件工程规范与开发流

本规范扩展项目的核心开发纪律，旨在通过静态分析、测试驱动开发（TDD）、架构分层隔离及变更验证门禁，保障代码质量与系统长期演进能力。

---

## 1. 静态分析与质量门禁（Lint & Build Gate）

- **零警告通过**：任何代码提交或任务结束前，必须通过 `dotnet build`，杜绝产生新的编译器警告或 Roslyn 分析警告。
- **空安全严格遵循**：C# 8+ Nullable 引用类型全局开启，严禁使用 `null!`（null-forgiving operator）掩盖设计缺陷，除非与不可修改的第三方库做边界互操作。
- **异常处理规范**：
  - 严禁空 `catch` 块（吞异常）。
  - 严禁使用未声明意图的宽泛 `catch (Exception)`，捕获异常必须记录诊断信息或转换为领域明确的异常。
  - 非托管资源必须使用 `using var` 或 `using (...)` 保证生命周期受控。

---

## 2. 测试驱动开发与验证门禁（TDD & Verification Gate）

- **测试先行原则**：
  - 修复 Bug 时，必须首先编写能够重现该 Bug 的失败单元测试（Red），再实现修复代码（Green）。
  - 新增核心算法、几何换算或数据转换时，同步提交对应的 xUnit 测试用例。
- **变更验证闭环**：
  - 代码变更完成后，必须运行 `dotnet test AutoCutPic.Tests/AutoCutPic.Tests.csproj` 确保测试全部通过。
  - 严禁在测试处于失败状态下交付任务。
- **边界条件覆盖**：
  - 几何计算必须覆盖极端比例（如 100:1、1:100）、非正输入（<= 0 宽高）、浮点精度临界值（偏移量边界 -0.5 / +0.5）。
  - 图像解码异常、破损文件、不支持格式必须有断言覆盖。

---

## 3. 架构分层与职责边界（Architecture Boundary）

- **Core 层（核心计算与领域模型）**：
  - 纯函数设计、无状态、无副作用，严禁依赖 WPF 相关命名空间（如 `System.Windows.Controls`）。
  - 保持高可测性，独立于外部 I/O 与具体 UI 控件。
- **ViewModels 层（业务状态与调度）**：
  - 负责状态维护、并发调度与命令绑定。
  - 严禁直接进行大量密集像素重采样与低层文件操作，必须将计算委托给 Core 处理器。
  - 所有涉及 UI 绑定的集合/属性变更必须调度在 UI 线程（Dispatcher）。
- **Views 层（UI 呈现与人机交互）**：
  - 严格聚焦在视觉呈现与输入事件转发，严禁包含业务几何计算。

---

## 4. 最小变更与依赖管理原则（Minimal Impact & Dependency）

- **最小作用范围**：严格围绕需求或修复点修改代码，禁止无端格式化无关文件或随意重构未变更逻辑。
- **依赖审慎引入**：禁止为了简单辅助函数引入新的 NuGet 依赖；通用工具函数优先在项目内部封装实现。
- **公共契约稳定**：保留对外的公开接口与数据结构兼容性，避免引起无谓的级联破坏。
